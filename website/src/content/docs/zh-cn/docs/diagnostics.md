诊断包含来源、行号与列号：

```text
interactive:1:6: undefined variable $missing
```

## 命令失败与退出码

普通命令返回非零退出状态时，当前脚本或交互提交批次停止执行。
条件位置允许检查非零退出状态，但程序不存在等启动错误仍会抛出异常。
原生管道返回最右侧失败阶段的非零退出状态，即使最后一个阶段成功也一样，包括上游因 SIGPIPE 退出的情况。
所有阶段的子进程都会被回收。

| 状态码 | 含义 |
| --- | --- |
| `0` | 执行成功 |
| 程序退出码 | 普通命令失败；失败管道阶段的退出码也会向上传递 |
| `2` | reader、语言或命令行参数错误 |
| `126` | 无执行权限 |
| `127` | 找不到命令 |
| `128 + signal` | 原生信号终止对应的兼容状态码 |

外部程序也可以自行选择这些退出码。完整结果可以区分正常退出与信号终止：
对 `$?`、`capture-call` 或 `wait` 返回的结果使用 `exit-code` 和 `signal` 查询。
`$?` 是 `CallResult`，不是数值状态码。

`exit` 接受 0 到 255 的退出码，默认为 0。即使在嵌套表达式或函数内也会退出会话，
退出前执行展开路径上的 `finally`，`catch` 不拦截它。在后台任务中则只结束该任务。

## 读取错误与提交批次

遇到顶层多余闭括号（`)`、`]` 或 `}`）时，reader 消耗该字符、报告错误并继续读取。
表达式内括号类型不匹配会报错；未完成的源码会指出未闭合的开括号。

文件、stdin 和 `-c` 脚本边读取边执行，因此较早的表达式可能在后续语法错误被发现前就已执行。
读取错误使状态码为 2，运行失败或显式退出可以覆盖它。运行失败后，reader 仍可诊断后续源码，
但不再执行后续表达式。

原生编辑器和浏览器终端在执行前检查整个提交批次。语法错误保留草稿，修改或清空后再提交。
运行错误停止当前批次，保留已经产生的效果，后续新输入仍可执行。浏览器会话退出后需重置。
浏览器未提供的命令会报告能力限制。

## 捕获错误

`try/catch/finally` 处理运行错误。`capture-call` 和 `wait` 把命令失败保留为可查询结果，
`check` 在结果失败时抛异常。捕获的 `Error` 暴露 `kind`、`message`、`code`、`offset`、`payload` 和 `result`：

| kind | 常见原因 |
| --- | --- |
| `runtime` | 变量未定义、操作数类型错误或结果 UTF-8 解码失败 |
| `command-failed` | 命令正常退出但状态非零 |
| `signaled` | 原生子进程被信号终止 |
| `spawn-failed` | 外部程序无法启动 |
| `output-limit` | 捕获输出超过 8 MiB |
| `json`、`bytes`、`http` | 对应的数据或请求操作失败 |
| `unsupported` | 当前运行时缺少所需能力 |
| `user` | `throw` 的参数不是已有 Error |
| `cancelled` | 原生后台任务被取消 |

reader 错误不能被 `try` 捕获。恢复、类型化 payload、清理与终止信息见[执行结果与后台任务](/parsh/zh-cn/docs/execution/)。

## 限制

reader 最多允许 256 层嵌套，求值最多 128 层；宏展开和显式捕获分别有独立的 32 层限制。
stdout/stderr 捕获共用 8 MiB 预算；浏览器额外的输出、文件系统和执行时限见[体验终端支持范围](/parsh/zh-cn/docs/playground/)。
